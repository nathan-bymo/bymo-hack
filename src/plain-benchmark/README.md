# Zero-shot benchmark on Kaggle

This is a single zero-shot stage with the same README/results organization as the training phases. Open [benchmark_apertus.ipynb](benchmark_apertus.ipynb) in Kaggle, enable Internet, attach the authorized competition data, set `INPUT_DIR` to its mounted directory, and add the Keera API key as the Kaggle secret `LLM_API_KEY`. The notebook stages the input in a fresh writable `/kaggle/working` directory because the prediction cache is written under the data directory. The dataset copy needs sufficient disk space. Each new run needs a fresh staging directory to prevent old cached responses from being mistaken for new measurements.

This is an API benchmark: Apertus 8B and 70B run on the hosted Keera gateway, so Kaggle GPU choice is not the model's inference GPU. The original gateway hardware and immutable model-service revisions are not recorded, and response identity cannot be guaranteed. Requests consume service quota.

The reconstructed P4 protocol uses 512² images, temperature 0, product context, five prompt/model variants, 32 images in parallel and 200 product-level bootstrap samples (seed 0). The product-hash split generates coverage (2,532 images), base (2,363) and prompt-test (1,193). Use the same authorized `train.csv`, images and `metric.py`; CSV and current prototype manifest hashes are recorded in [micro-training phase 2](../micro-training/phase-2/README.md). Split counts were independently checked against the current local data; image byte identity and historical endpoint revisions remain unverified. [Results](RESULTS.md).
